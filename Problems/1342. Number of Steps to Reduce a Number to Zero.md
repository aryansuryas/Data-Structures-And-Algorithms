# LeetCode 1342: Number of Steps to Reduce a Number to Zero

## 🎯 Goal
The function calculates the total number of operations required to reduce a non-negative integer `num` to zero. It uses a **simulative greedy approach**, dividing the number by 2 if it is even, or subtracting 1 if it is odd, tracking the process inside a simple `while` loop.

## 🛠️ Code Implementation
```cpp
#include <iostream>

using namespace std;

class Solution {
public:
    int numberOfSteps(int num) {
        int steps = 0; // Counter to track the total number of operations
        
        while (num != 0) { // Continue looping until the number is reduced to zero
            if (num % 2 == 0) { // Check if the current number is even
                num = num / 2;  // Divide the number by 2
                steps++;        // Increment the step count
            } else {            // Execution falls here if the number is odd
                num = num - 1;  // Subtract 1 to make it even (or zero)
                steps++;        // Increment the step count
            }
        }
        return steps; // Return the final count of operations
    }
};
```

## 🔄 Trace Example (num = 14)

| Step | Initial `num` | Condition Checked | Action Performed | Resulting `num` | Cumulative `steps` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 14 | `num % 2 == 0` (Even) | `14 / 2` | 7 | 1 |
| 2 | 7 | `else` (Odd) | `7 - 1` | 6 | 2 |
| 3 | 6 | `num % 2 == 0` (Even) | `6 / 2` | 3 | 3 |
| 4 | 3 | `else` (Odd) | `3 - 1` | 2 | 4 |
| 5 | 2 | `num % 2 == 0` (Even) | `2 / 2` | 1 | 5 |
| 6 | 1 | `else` (Odd) | `1 - 1` | 0 | 6 |

**Result:** `6`

## ⚠️ Edge Cases Handled
* **Minimum Value Bound (`num = 0`):** The `while` loop condition `num != 0` immediately evaluates to false, causing the function to skip the loop entirely and safely return `0` steps.
* **Power of Two Inputs:** If the input is a perfect power of two (e.g., 8), it executes exactly one subtraction step at the very end (`1 - 1`), while all preceding steps are pure divisions.

## 💡 Key Takeaways
* **Bitwise Alternative Thinking:** Every odd number ends with a `1` in binary (requiring a subtraction to turn to `0`), and every even number ends with `0` (requiring a right bit-shift). This problem acts as a perfect gateway to learning **Bitwise Manipulation**.
* **Simulative Looping structures:** A simple `while` loop structure is ideal here because the number of iterations cannot be predetermined linearly like a `for` loop, dynamically relying on the parity changes of `num`.

## ⚡ Complexity Analysis
* **Time Complexity:** \(O(\log n)\)
  * In the worst-case scenario (odd numbers), it takes at most 2 operations to reduce the value of the number by half, mapping directly to logarithmic time proportional to the number of binary bits.
* **Space Complexity:** \(O(1)\)
  * The algorithm runs entirely in-place, requiring a single primitive integer variable (`steps`) to store the count without using any dynamic or auxiliary memory structures.
