# LeetCode 33: Search in Rotated Sorted Array

## 🎯 Goal
This function finds the index of a target value within a sorted array that has been rotated at an unknown pivot point. It uses a modified **Binary Search** strategy to identify which half of the array is sorted and narrow down the search space in logarithmic time.

## 🛠️ Code Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int low = 0;
        int high = nums.size() - 1;

        while (low <= high) {
            // Safe mid calculation to prevent integer overflow
            int mid = low + (high - low) / 2;

            if (nums[mid] == target)
                return mid; // Target found, return index immediately

            // Check if the left half is sorted
            if (nums[low] <= nums[mid]) {
                // Check if target lies within the sorted left half
                if (nums[low] <= target && target < nums[mid])
                    high = mid - 1; // Narrow search to left half
                else
                    low = mid + 1;  // Narrow search to right half
            } 
            // Otherwise, the right half must be sorted
            else {
                // Check if target lies within the sorted right half
                if (nums[mid] < target && target <= nums[high])
                    low = mid + 1;  // Narrow search to right half
                else
                    high = mid - 1; // Narrow search to left half
            }
        }

        return -1; // Target does not exist in the array
    }
};
```

## 🔄 Trace Example (`nums = [4, 5, 6, 7, 0, 1, 2]`, `target = 0`)

| Step | low | high | mid | nums[mid] | Sorted Half | Condition Check | Action |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | 0 | 6 | 3 | 7 | Left (`4 <= 7`) | `0` is not between `4` and `7` | `low = mid + 1` (4) |
| **2** | 4 | 6 | 5 | 1 | Right (`1 <= 2`) | `0` is not between `1` and `2` | `high = mid - 1` (4) |
| **3** | 4 | 4 | 4 | 0 | Left (`0 <= 0`) | `nums[mid] == target` | Return `mid` (4) |

**Result:** The target value `0` is found at index **4**.

## ⚠️ Edge Cases Handled
* **Target Not Present**: Pointers safely cross each other (`low > high`) when the element is missing, returning `-1`.
* **Single Element Array**: Evaluates the sole element immediately and either returns `0` or exits to return `-1`.
* **Array Not Rotated**: If the array is standard sorted, `nums[low] <= nums[mid]` remains true throughout, executing like standard binary search.
* **Pivot at Boundaries**: Safely handles cases where rotation happens at the very beginning or end of the vector array.

## 💡 Key Takeaways
* **One Half is Always Sorted**: In a rotated sorted array, splitting the array in half will always yield at least one perfectly sorted subarray.
* **Strict Range Checks**: Using relational operators (`<=`) ensures boundary elements are accurately captured when verifying if a target falls within a sorted sub-range.
* **Logarithmic Performance**: By evaluating conditions on the sorted half, the algorithm discards 50% of the elements each step without needing to locate the pivot first.

## ⚡ Complexity Analysis
* **Time Complexity:** **$\mathcal{O}(\log N)$** because the search range is halved during each iteration of the loop.
* **Space Complexity:** **$\mathcal{O}(1)$** as the searching logic runs in-place using only pointers without allocating extra memory structures.
