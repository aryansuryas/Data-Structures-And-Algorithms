# LeetCode 34: Find First and Last Position of Element in Sorted Array

## 📝 Problem Description
Given an array of integers `nums` sorted in non-decreasing order, find the starting and ending position of a given `target` value.

If `target` is not found in the array, return `[-1, -1]`.

You must write an algorithm with **$O(\log n)$** runtime complexity.

---

## 💡 Solution Approach (Modified Binary Search)
Since the array is already sorted, a standard linear scan would take $O(n)$ time, which is too slow. Instead, we use two separate **Binary Searches**:

1. **`findfirst`**: Finds the leftmost (first) occurrence of the target. When we find a match (`arr[mid] == el`), we record the index and shift our right pointer (`high = mid - 1`) to check if the same element appears earlier.
2. **`findlast`**: Finds the rightmost (last) occurrence of the target. When we find a match, we record the index and shift our left pointer (`low = mid + 1`) to check if the same element appears later.

---

## 💻 Code Implementation (C++)

```cpp
class Solution {
private:
    // Helper function to find the first occurrence of the element
    int findfirst(vector<int>& arr, int el) {
        int low = 0;                  
        int high = arr.size() - 1;    
        int ans = -1;
        
        while (low <= high) {
            int mid = low + (high - low) / 2; // Prevents integer overflow
            
            if (arr[mid] == el) {
                ans = mid;
                high = mid - 1;       // Keep looking left for the first occurrence
            } else if (arr[mid] > el) {
                high = mid - 1;       // Target is smaller, look left
            } else {
                low = mid + 1;        // Target is larger, look right
            }
        }
        return ans;
    }

    // Helper function to find the last occurrence of the element
    int findlast(vector<int>& arr, int el) {
        int low = 0;
        int high = arr.size() - 1;
        int ans = -1;
        
        while (low <= high) {
            int mid = low + (high - low) / 2; 
            
            if (arr[mid] == el) {
                ans = mid;
                low = mid + 1;        // Keep looking right for the last occurrence
            } else if (arr[mid] > el) {
                high = mid - 1;       // Target is smaller, look left
            } else {
                low = mid + 1;        // Target is larger, look right
            }
        }
        return ans;
    }

public:
    vector<int> searchRange(vector<int>& nums, int target) {
        // Return both results wrapped in a single vector
        return {findfirst(nums, target), findlast(nums, target)};
    }
};
```

## 🛠️ Step-by-Step Walkthrough

Let's dry-run the code with `nums = [1, 3, 5, 5, 5, 5, 7]`, `target = 5`.

### Part 1: Executing `findfirst`
* **Initial:** `low = 0`, `high = 6`, `ans = -1`
* **Iteration 1:** `mid = 3`, `nums[3] = 5`. Match found! 
  * Update `ans = 3`. 
  * Look left: `high = mid - 1 = 2`.
* **Iteration 2:** `low = 0`, `high = 2`, `mid = 1`, `nums[1] = 3`. 
  * `3 < 5`, so look right: `low = mid + 1 = 2`.
* **Iteration 3:** `low = 2`, `high = 2`, `mid = 2`, `nums[2] = 5`. Match found! 
  * Update `ans = 2`. 
  * Look left: `high = mid - 1 = 1`.
* **End:** Loop breaks because `low (2) > high (1)`. Returns **`2`**.

### Part 2: Executing `findlast`
* **Initial:** `low = 0`, `high = 6`, `ans = -1`
* **Iteration 1:** `mid = 3`, `nums[3] = 5`. Match found! 
  * Update `ans = 3`. 
  * Look right: `low = mid + 1 = 4`.
* **Iteration 2:** `low = 4`, `high = 6`, `mid = 5`, `nums[5] = 5`. Match found! 
  * Update `ans = 5`. 
  * Look right: `low = mid + 1 = 6`.
* **Iteration 3:** `low = 6`, `high = 6`, `mid = 6`, `nums[6] = 7`. 
  * `7 > 5`, so look left: `high = mid - 1 = 5`.
* **End:** Loop breaks because `low (6) > high (5)`. Returns **`5`**.

**Final Output:** `[2, 5]`

---

## 📊 Complexity Analysis

* **Time Complexity:** **$\mathcal{O}(\log n)$**
  * We execute two completely independent binary searches. 
  * Each binary search takes $\mathcal{O}(\log n)$ steps to divide the search space in half. 
  * Total time is $\mathcal{O}(\log n) + \mathcal{O}(\log n) = \mathcal{O}(2 \log n)$, which simplifies to $\mathcal{O}(\log n)$.

* **Space Complexity:** **$\mathcal{O}(1)$**
  * The algorithm modifies pointers (`low`, `high`, `mid`) in place.
  * No extra temporary collections, recursion frames, or dynamic arrays are generated.
