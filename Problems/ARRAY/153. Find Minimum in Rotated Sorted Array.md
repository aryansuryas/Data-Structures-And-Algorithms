# LeetCode 153: Find Minimum in Rotated Sorted Array

## 🎯 Goal
This function finds the minimum element in a sorted array that has been rotated. It uses an optimized **Binary Search** technique to identify the sorted halves, track the smallest values, and isolate the absolute minimum element in logarithmic time.

## 🛠️ Code Implementation
```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int l = 0;
        int r = nums.size() - 1;
        int ans = INT_MAX; // Initialize to maximum possible value

        while (l <= r) {
            int mid = l + (r - l) / 2; // Avoids integer overflow

            // If the current search space is already sorted,
            // the minimum in this range is always at index 'l'
            if (nums[l] <= nums[r]) {
                ans = min(ans, nums[l]);
                break; // No need to search further
            }

            // If the left half is sorted
            if (nums[l] <= nums[mid]) {
                ans = min(ans, nums[l]); // Track the smallest in the sorted left half
                l = mid + 1;             // Search the remaining right half
            } 
            // Otherwise, the right half must be sorted
            else {
                ans = min(ans, nums[mid]); // Track the mid element as a candidate minimum
                r = mid - 1;               // Search the remaining left half
            }
        }
        return ans;
    }
};
```

## 🔄 Trace Example (`nums = [4, 5, 6, 7, 0, 1, 2]`)

| Step | l | r | mid | nums[mid] | Condition Check | Action | ans |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | 0 | 6 | 3 | 7 | `nums[0] > nums[6]` (4 > 2)<br>`nums[0] <= nums[3]` (4 <= 7) | Left half sorted. `ans = min(INT_MAX, 4)`. `l = mid + 1` (4). | 4 |
| **2** | 4 | 6 | 5 | 1 | `nums[4] <= nums[6]` (0 <= 2) | Whole range sorted. `ans = min(4, 0)`. `break`. | 0 |

**Result:** The minimum value in the array is **0**.

## ⚠️ Edge Cases Handled
* **Array Not Rotated**: If the array is already fully sorted, `nums[l] <= nums[r]` fires immediately on step 1, updating `ans` to `nums[0]` and exiting cleanly.
* **Single Element Array**: The loop runs once, passes the `nums[l] <= nums[r]` check, sets `ans = nums[0]`, and returns it safely.
* **Two Element Array**: Correctly identifies the smaller of the two elements through boundary collapsing without getting stuck in an infinite loop.
* **Integer Overflow Avoidance**: Calculates the index midpoint via `l + (r - l) / 2` to stay safely within numeric limits.

## 💡 Key Takeaways
* **Early Exit Optimization**: Checking `nums[l] <= nums[r]` eliminates unnecessary steps if a subarray is already fully sorted.
* **Isolating the Pivot**: When one section is sorted, the minimum element always hides in either the lowest boundary of that sorted section or inside the opposite unsorted section.
* **Constant Tracking Variable**: Using an independent `ans` tracking variable ensures that candidate solutions are never lost during partition skipping operations.

## ⚡ Complexity Analysis
* **Time Complexity:** **$\mathcal{O}(\log N)$** as the binary search space cuts in half with every iteration step.
* **Space Complexity:** **$\mathcal{O}(1)$** because it uses a constant amount of extra space for tracking pointers and minimum variables.
