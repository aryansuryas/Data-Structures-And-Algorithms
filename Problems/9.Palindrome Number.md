# LeetCode 9: Palindrome Number

## 🎯 Goal
The function determines whether an integer `x` is a palindrome (reads the same forward and backward) without converting it into a string. It achieves this via a **Half-Reversal pattern**, reversing only the right half of the digits to prevent potential integer overflow risks entirely.

## 🛠️ Code Implementation

### Method 1: Half Reversal (Using Explicit Digit Extraction Variable)
```cpp
#include <iostream>

using namespace std;

class Solution {
public:
    bool isPalindrome(int num) {
        // Base edge case: Negatives are never palindromes. 
        // Numbers ending in 0 can't be palindromes (no leading zeros allowed) except 0 itself.
        if (num < 0 || (num % 10 == 0 && num != 0)) return false;

        long rev = 0; // Using long accumulator to fully guard against any overflow
        
        // Loop terminates as soon as the reversed right half catches up to or exceeds the left half
        while (num > rev) {
            int digit = num % 10;    // Extract the rightmost trailing digit
            rev = rev * 10 + digit;  // Push the extracted digit onto the reversed half accumulator
            num = num / 10;          // Chop off the rightmost digit from the original number
        }
        
        // Check 1: rev == num -> Handles even-length palindromes (e.g., 1221 -> 12 == 12)
        // Check 2: rev / 10 == num -> Handles odd-length palindromes, stripping the middle element (e.g., 12321 -> 12 == 123/10)
        return rev == num || rev / 10 == num;
    }
};
```

### Method 2: Inline Half Reversal (Memory-Optimized Space Variation)
```cpp
#include <iostream>

using namespace std;

class Solution {
public:
    bool isPalindrome(int x) {
        // Guard check for negatives and trailing zero numbers
        if (x < 0 || (x % 10 == 0 && x != 0))
            return false;

        int rev = 0; // Keeping accumulator as int to conserve registers

        while (x > rev) {
            // Inline arithmetic reduces temporary allocations on the call stack
            rev = rev * 10 + x % 10;
            x /= 10;
        }

        // Return check matching structural halves
        return x == rev || x == rev / 10;
    }
};
```

## ⚠️ Edge Cases Handled
* **Negative Ints bounded safely:** Any input with a minus sign (e.g., `-121`) is rejected instantly by `x < 0`.
* **Trailing Zero Traps:** Numbers like `10`, `130`, or `1200` fail immediately because no standard base-10 integer can begin with leading zeros to balance them.
* **The Absolute Zero Origin (`x = 0`):** Specifically exempted by `x != 0` within the safety filter, running correctly to return `true`.

## 💡 Key Takeaways
* **Inlining Arithmetic:** Method 2 completely eliminates the local variable assignment for `int digit`, calculating everything inline inside the accumulator statement to optimize stack frames.
* **Overflow Protection:** Because the loop condition halts exactly at the center point (`x > rev`), the `rev` variable never has the chance to double its size, removing any mathematical risk of integer overflow.

## ⚡ Complexity Analysis
* **Time Complexity:** \(O(\log_{10} n)\)
  * The total number of division iterations scale directly with the overall number of base-10 digits in the integer, slicing the target range in half.
* **Space Complexity:** \(O(1)\)
  * Operates entirely in place, allocating only a pair of tracking variables (`rev`, `digit`) independent of the input size.
